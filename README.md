# Meal Tracker

A small, private calorie and macro tracker for iPhone. It shows what's **left** today and this week.

- **No account, no server.** Everything is stored on your phone in the browser's database (IndexedDB).
- **Free hosting.** GitHub Pages serves the files; you install it from Safari with *Add to Home Screen*.
- **No build step.** Plain HTML, CSS and JavaScript modules. Open a file, change it, refresh.

## What's in version 1

| Screen | What it does |
|---|---|
| Welcome | First launch only |
| Targets | Your goal (calorie **deficit** or **surplus**), daily calories + grams of protein/carbs/fat. Checks that macros add up to your calories. Changes apply from today onward; history is kept. |
| Today | Calories left (ring), macros left (bars), the day's entries. Tap an entry to change its amount or group, or delete it. **‹ ›** switch days and tapping the date opens a calendar: any past day can be viewed, added to and edited. |
| Week | Week budget left (Monday start, changeable), per-day bars against each day's target, average macros. |
| Add food | **Recent** shows what you logged on previous days, by day and group: tap to add again (same amount and group, both changeable) or **Add all** for a whole meal. **Press and hold** an item to select several (from any days), then **Add** them together, keeping their groups or putting them all in one. Also My foods, search your foods and the USDA database, scan a barcode (Open Food Facts), amount in grams with live macros, optional group (Breakfast, Lunch, Dinner or your own). Foods you log from search or scans are saved to My foods. |
| Create food | Enter a food from its label, per 100 g or per serving, or **fill it from a photo of the label** (OCR on the phone). Stored per 100 g. Edit or delete later from *My foods*. |
| Servings | Serving sizes in g, ml, oz, fl oz, **tsp, tbsp, cup** (e.g. "2 tbsp (32 g)", weight optional) or **pieces** (e.g. "2 cookies", weight optional). Log in pieces, servings, g/ml, oz/fl oz or tsp/tbsp/cup (1 tsp = 5 ml, 1 tbsp = 15 ml, 1 cup = 240 ml; for weighed foods the label's spoon weight is used, else ≈ 1 g per ml); the app remembers the unit you used last. The unit is a dropdown (like Create food) with **pieces** always listed; picking it for a food without pieces asks once (e.g. "1 serving = 6 pieces"), including scanned foods and entries you're editing. Scans read pieces from the package text when it has them ("About 11 chips"). |
| Settings | Profile, targets, meal groups, week start, back up and restore. |
| Trends | Week / Month / Year: **average daily deficit or surplus vs your target** (green when it matches your goal, rust when it doesn't), calories vs your stepped target line (tap a bar for details), days within ±10% of target, protein goal days, macro split vs target. Only logged days count. |

### Where food data comes from

- **Barcodes → [Open Food Facts](https://world.openfoodfacts.org)**, a free crowd-sourced database of packaged foods. No key needed. If a product isn't there, you enter its label once and the barcode is saved with your food.
- **Search → [USDA FoodData Central](https://fdc.nal.usda.gov)**, generic foods like "bananas, raw". A free api.data.gov key is built into `js/food-api.js` (shared by everyone, about 1,000 searches an hour). Anyone can paste their own free key from [api.data.gov/signup](https://api.data.gov/signup/) in Settings to use theirs instead.
- **Label photos** are read on the phone with [Tesseract.js](https://github.com/naptha/tesseract.js) (Apache-2.0), saved in `vendor/tesseract`. The first use downloads about 7 MB; after that it works offline. `js/label-parser.js` turns the recognized text into numbers.
- Barcodes are read from a photo taken with the phone camera (no camera-permission prompt) using [ZXing](https://github.com/zxing-js/browser) (MIT license), saved in `vendor/`.

## How the code is organized

```
index.html              the one HTML page; loads css/styles.css and js/app.js
manifest.webmanifest    tells the phone the app's name, icon and colors
sw.js                   service worker: keeps a copy of the files so the app opens offline
css/styles.css          all styling; colors are variables at the top
js/app.js               router: reads the URL hash (#/today, #/week ...) and shows that screen
js/db.js                tiny IndexedDB wrapper (get, put, delete, list)
js/store.js             app data rules: targets, foods, entries, backup
js/ui.js                shared pieces: tab bar, bottom sheets, toast, the amount sheet
js/util.js              helpers: dates, number formatting, nutrition math, icons
js/views/*.js           one file per screen; each exports a function that draws the screen
icons/                  app icons (generated by tools/make_icons.py)
```

**How a screen works:** each view function builds an HTML string, puts it in the page, then listens for taps
on elements marked `data-act="..."`. When data changes, the view simply redraws itself.

**How data is stored:** foods are kept **per 100 g**; an entry stores the grams you ate plus a copy of the
food's values, so editing a food later never changes your history. Targets are a list of
`{ from: date, kcal, p, c, f }`; a day uses the latest target that started on or before it.

## Run it on your computer

```bash
cd meal-tracker
python3 -m http.server 8000
# open http://localhost:8000 in a browser
```

(It needs to be served over http, not opened as a file, because it uses JavaScript modules and a service worker.)

## Publish and install

1. Repo → **Settings → Pages** → *Source: Deploy from a branch* → Branch **main**, folder **/ (root)** → Save.
2. After a minute it's live at `https://<username>.github.io/meal-tracker/`.
3. On iPhone, open that link in **Safari** → **Share** → **Add to Home Screen**.

Every `git push` to `main` updates the live app within a minute or two. Open the app while online to pick up the new version.

## Backups

Your data lives only on your phone. Use **Settings → Back up my data** now and then and save the file to iCloud Drive / Files.
To move to a new phone, install the app there and use **Restore from a backup**.
